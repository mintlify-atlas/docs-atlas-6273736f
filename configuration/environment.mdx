## Overview

Laravel uses environment variables to manage configuration that varies between environments (development, staging, production). All environment variables are stored in the `.env` file at the root of your application.

<Note>The `.env` file should never be committed to version control, as it contains sensitive credentials.</Note>

## Environment File

When you install Laravel, a `.env.example` file is included. You should copy this to `.env` and customize it for your environment:

```bash
cp .env.example .env
```

### Application Configuration

```bash .env
APP_NAME=Laravel
APP_ENV=local
APP_KEY=
APP_DEBUG=true
APP_URL=http://localhost
```

<AccordionGroup>
  <Accordion title="APP_NAME">
    The name of your application. Used in emails, notifications, and other places.
    
    **Default:** `Laravel`
  </Accordion>

  <Accordion title="APP_ENV">
    The environment your application is running in.
    
    **Options:** `local`, `development`, `staging`, `production`
    
    **Default:** `local`
  </Accordion>

  <Accordion title="APP_KEY">
    A 32-character encryption key used for encrypting cookies, sessions, and other encrypted data.
    
    <Warning>Generate this immediately after installation using `php artisan key:generate`</Warning>
  </Accordion>

  <Accordion title="APP_DEBUG">
    Enable detailed error pages with stack traces.
    
    **Options:** `true`, `false`
    
    **Default:** `true` (local), `false` (production)
    
    <Warning>Never set this to `true` in production, as it exposes sensitive information</Warning>
  </Accordion>

  <Accordion title="APP_URL">
    The URL where your application is accessible.
    
    **Example:** `https://example.com`
  </Accordion>
</AccordionGroup>

### Localization Settings

```bash .env
APP_LOCALE=en
APP_FALLBACK_LOCALE=en
APP_FAKER_LOCALE=en_US
```

- **APP_LOCALE** - Default language for the application
- **APP_FALLBACK_LOCALE** - Fallback language when translation is missing
- **APP_FAKER_LOCALE** - Locale for generating fake data in tests and seeders

### Maintenance Mode

```bash .env
APP_MAINTENANCE_DRIVER=file
# APP_MAINTENANCE_STORE=database
```

Laravel's maintenance mode can store state in either:
- `file` - Stores in `storage/framework/maintenance.php`
- `database` - Stores in the cache database table

### Security Settings

```bash .env
BCRYPT_ROUNDS=12
```

**BCRYPT_ROUNDS** - Controls the cost of bcrypt hashing. Higher values are more secure but slower.

<Info>The default of 12 rounds provides good security with acceptable performance.</Info>

### Logging Configuration

```bash .env
LOG_CHANNEL=stack
LOG_STACK=single
LOG_DEPRECATIONS_CHANNEL=null
LOG_LEVEL=debug
```

<AccordionGroup>
  <Accordion title="LOG_CHANNEL">
    The default logging channel to use.
    
    **Options:** `stack`, `single`, `daily`, `syslog`, `errorlog`
    
    **Default:** `stack`
  </Accordion>

  <Accordion title="LOG_LEVEL">
    Minimum log level to record.
    
    **Options:** `debug`, `info`, `notice`, `warning`, `error`, `critical`, `alert`, `emergency`
    
    **Default:** `debug` (local), `error` (production)
  </Accordion>
</AccordionGroup>

### Performance Settings

```bash .env
# PHP_CLI_SERVER_WORKERS=4
```

**PHP_CLI_SERVER_WORKERS** - Number of worker processes for the PHP built-in server.

<Tip>Increase this value on multi-core systems for better development performance.</Tip>

### Mail Configuration

```bash .env
MAIL_MAILER=log
MAIL_SCHEME=null
MAIL_HOST=127.0.0.1
MAIL_PORT=2525
MAIL_USERNAME=null
MAIL_PASSWORD=null
MAIL_FROM_ADDRESS="hello@example.com"
MAIL_FROM_NAME="${APP_NAME}"
```

<Note>In local development, the `log` mailer writes emails to the log file instead of sending them.</Note>

### AWS Configuration

```bash .env
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
AWS_DEFAULT_REGION=us-east-1
AWS_BUCKET=
AWS_USE_PATH_STYLE_ENDPOINT=false
```

Used for S3 file storage, SQS queues, and other AWS services.

### Vite Configuration

```bash .env
VITE_APP_NAME="${APP_NAME}"
```

Environment variables prefixed with `VITE_` are exposed to your frontend JavaScript code.

## Accessing Environment Variables

### In Configuration Files

Use the `env()` helper function:

```php config/app.php
'name' => env('APP_NAME', 'Laravel'),
```

<Warning>Never call `env()` outside of configuration files. Always access config values using `config()`</Warning>

### In Application Code

Use the `config()` helper:

```php
$appName = config('app.name');
$debug = config('app.debug');
```

## Environment Detection

Detect the current environment:

```php
use Illuminate\Support\Facades\App;

if (App::environment('local')) {
    // Running in local environment
}

if (App::environment(['local', 'staging'])) {
    // Running in local or staging
}

if (App::isProduction()) {
    // Running in production
}
```

## Best Practices

<Steps>
  <Step title="Keep .env out of version control">
    Add `.env` to your `.gitignore` file. Only commit `.env.example` with safe default values.
  </Step>

  <Step title="Use different values per environment">
    Maintain separate `.env` files for local, staging, and production with appropriate values for each.
  </Step>

  <Step title="Document all variables">
    Keep `.env.example` updated with all required variables and helpful comments.
  </Step>

  <Step title="Validate critical variables">
    Check that required environment variables are set during application bootstrap.
  </Step>
</Steps>
